## Start with a problem

The mistake already happened: the command ran, the output looks wrong. The real danger isn't the loss itself — it's panic-follow-ups that destroy the recoverable state. This article walks the recovery path for Recover after an accidental merge ahead of time: what to do first, what next, and what never to do.

## Key checks

1. Has the merge commit been pushed?
2. Has anyone branched from it?

## First inspection

```bash
git log --oneline --graph --decorate -n 20
git branch -vv
git reflog
```

## Recovery options

### Merge not shared

```bash
git reset --hard HEAD~1
```

### Merge already shared

```bash
git revert -m 1 <merge-commit>
```

`-m 1` keeps the first-parent perspective.

<WarningBox title="Confirm parent selection before `revert -m`">
  Choosing the wrong parent can revert the wrong side of history and create additional recovery work.
</WarningBox>
