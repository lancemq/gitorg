---

**1. git-bisect.mdx**
- **问题类型**: 事实错误 / 概念性错误（严重）
- **具体问题**:
  - "典型用例"段落称 `git bisect` 用于"合并、回滚、挑提交或整理提交序列时…重塑历史表达"——**完全错误**。`git bisect` 是纯只读命令，用于二分查找引入 bug 的提交，绝不改写历史。
  - "图例理解"输出为"新的提交关系|移动后的引用|可恢复路径"——完全错误，bisect 不产生新提交关系，不移动引用。
  - "这条命令在流程里解决什么问题"称其"直接影响历史表达、引用位置或提交之间的关系"——完全错误。
- **建议修正**: 将后三段模板替换为正确的描述：bisect 是只读排查工具，帮助定位问题提交，不影响仓库历史。

## 根因分析

大部分问题来源于 **模板化内容生成** 的系统性错误。多个教程的后半段章节（"这条命令在流程里解决什么问题"、"典型用例"、"图例理解"、"特殊情况与边界"）套用了错误的模板分类：

1. **"远端/补丁"模板** 被错误套用到 archive、bundle、clone、request-pull、send-email 等命令上
2. **"历史命令"模板** 被错误套用到 bisect、cherry、cherry-pick、merge-base、mergetool、notes、range-diff、reflog、revert 等命令上（其中 cherry-pick/merge/rebase/reset 确实是历史命令，但 bisect/cherry/reflog 等不是）
3. **"底层命令/plumbing"模板** 被错误套用到 ls-files、ls-tree、merge-base、rev-list、rev-parse、symbolic-ref 等只读命令上（输出描述暗示会"更新低层状态"）
4. **"观察类"模板** 被错误套用到 describe、grep、shortlog、show-ref 等命令上
5. **"工作副本"模板** 被错误套用到 sparse-checkout、submodule、worktree 等命令上
6. **"状态类"模板** 被错误套用到 tag 等命令上

**最严重的问题** 是将纯只读命令（如 git bisect、git cherry、git merge-base）描述为"重塑历史表达"的命令，这是完全错误的。
