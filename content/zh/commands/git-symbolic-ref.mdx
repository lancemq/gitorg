# git-symbolic-ref 教程

## 先想一个问题

HEAD 不是一个提交，是一个指向分支的符号引用。`git symbolic-ref` 读写的就是这层"指向"。它解释了两件常被误解的事：为什么 detached HEAD 时 `git branch` 标不出当前分支，以及切分支时 HEAD 究竟被改成了什么。

## 基本示例

```bash
git symbolic-ref HEAD
```

## 脚本里判断 detached HEAD

```bash
if git symbolic-ref -q HEAD >/dev/null; then
  echo "在分支上：$(git symbolic-ref --short HEAD)"
else
  echo "detached HEAD，正站在 $(git rev-parse --short HEAD)"
fi
```

`-q` 让「不是符号引用」走静默失败（退出码 1）而不是报错文本；`--short` 把 `refs/heads/main` 缩成 `main`。`git branch --show-current` 是这两步的合体版，但老版本 git 没有，脚本里 symbolic-ref 兼容性最好。

## 特殊情况与边界

- `git symbolic-ref` 是读写命令：只传引用名时读取其值，传入第二个参数时设置新值。
- HEAD 是一个符号引用，指向当前所在分支。如果 HEAD 直接指向 commit hash（detached HEAD），`git symbolic-ref HEAD` 会报错。
- 写入操作直接修改引用文件，绕过了 `git checkout` 或 `git switch` 的安全保护，可能导致工作区与 HEAD 不一致。
- 如果目标引用不存在，`symbolic-ref` 仍然可以创建符号引用指向它，但这可能导致后续命令出错。
- 使用 `-d` 可以删除一个符号引用，删除 HEAD 会让仓库处于无 HEAD 状态，通常不应这样做。
