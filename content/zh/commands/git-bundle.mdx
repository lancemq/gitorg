# git-bundle 教程

## 学完这篇你会掌握什么

- 把 Git 历史打包成单文件用于离线传输或受限网络同步，适合“不能直接 fetch/push”的场景。
- 只打包需要的 ref 范围（`--all` 往往不是最优），并在分发前用 `git bundle verify` 确认前置对象齐全。

## 一句话理解

`git bundle` 能把仓库引用与对象打成一个可传输文件，接收方可以像远端一样读取它。

## 什么时候适合用

- 内网隔离、无公网访问
- 一次性传递特定分支历史
- 做可归档的历史快照交付

## 典型命令

```bash
git bundle create repo.bundle main feature/hotfix
git bundle verify repo.bundle
git clone repo.bundle repo-from-bundle
```

## 常见工作流

1. 发送方创建 bundle 并校验
2. 通过文件渠道传递 bundle
3. 接收方 `clone` 或 `fetch` 这个 bundle

## 关键边界

- bundle 里有什么，完全取决于你打包了哪些 ref
- 接收方若缺前置对象，可能无法完整应用增量 bundle

<WarningBox title="先 verify 再分发">
  bundle 文件一旦在外部渠道传播，返工成本高。生成后立即 `git bundle verify` 能提前暴露缺失依赖问题。
</WarningBox>

## 常见误区

### 误区 1：以为 `--all` 总是最佳选项

很多场景只需要最小引用集，盲目全量会造成大文件和泄露风险。

### 误区 2：不校验就给接收方

接收方失败后再排查，沟通与传输成本会放大。

### 误区 3：把 bundle 当长期实时同步方案

bundle 更适合“批量快照式”交换，不适合高频双向协作。

## 增量传输：只带上次之后新增的提交

全量 bundle 的体积和仓库历史成正比，日常传递更常用的是「以某个已有提交为基线」的增量包：`git bundle` 直接把参数交给 `rev-list`，所以范围表达式照常可用。

```bash
# 只打包 v1.2 之后 main 上新增的提交
git bundle create updates.bundle v1.2..main

# 同时带上两个分支，排除对方一定已有的基线
git bundle create updates.bundle ^v1.2 main release

# 打包前先看清单：包含哪些 ref、每个 ref 指向哪个提交
git bundle list-heads updates.bundle

# 接收端验证：会逐条打印 refs，并检查前置提交是否齐全
git bundle verify updates.bundle
```

`verify` 失败时最典型的报错是：

```
error: Repository lacks these prerequisite commits:
error: 3f2a91c... (v1.2)
```

这表示接收端没有 `v1.2` 及更早的历史，增量包无法单独使用。解决方式只有两种：让对方先补齐这段历史，或者改用对端已有提交作为新的基线重新打包。**这个错误在打包端完全看不出来**，所以 `verify` 必须在分发前跑，而不是等接收方报错。

## 接收端怎么用

```bash
# 从 bundle 增量更新已有仓库（推荐：落到远端跟踪分支，不直接改动当前分支）
git fetch ../updates.bundle main:refs/remotes/bundle/main

# 从零创建仓库：要求 bundle 里包含 HEAD
git clone repo.bundle repo-from-bundle

# 只解包对象、不建引用，适合先检查内容再决定怎么接
git bundle unbundle updates.bundle
```

`git clone` 一个 bundle 时，要求包里含有 `HEAD` 引用——用 `git bundle create repo.bundle --all` 生成的包满足这一点；如果只打了某个分支的范围（如 `v1.2..main`），clone 会失败，只能走 `fetch`。这是「bundle 能不能直接 clone」的实际分界线。

## 什么时候不该用 bundle

- **高频双向协作**：每次都要重新打包、传递、验证，成本远高于直接 `push`/`fetch`。bundle 是快照交换，不是同步通道。
- **需要匿名只读分发**：这种情况 `git daemon`、静态 HTTP 或平台归档更省事。
- **包含敏感路径的全量历史**：`--all` 会把所有 ref 的历史一起带出去，打包前先确认没有不该外传的分支和标签。
