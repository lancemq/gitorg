# git-update-ref 教程

## 基本示例

```bash
git update-ref refs/heads/feature HEAD       # 指向 HEAD 的提交
git update-ref refs/heads/feature 3a91f2c    # 指向指定提交
git update-ref -d refs/heads/feature         # 删除引用
git update-ref --no-deref HEAD 3a91f2c       # 不解析符号引用，直接改 HEAD 本身
```

## 带旧值校验：引用的 CAS

最后一个参数可以写「期望的旧值」，值对不上就拒绝——引用级别的 compare-and-swap：

```bash
# 只有当 feature 现在指向 aaaa111 时才改成 bbbb222
git update-ref refs/heads/feature bbbb222 aaaa111
# error: cannot lock ref ...: expected aaaa111 but got cccc333 时拒绝执行
```

并发脚本（比如多个 job 同时操作同一引用）必须用它，否则就是丢失更新。

## 事务：stdin 模式

多条更新要么全成功要么全不做：

```bash
git update-ref --stdin <<'EOF'
start
update refs/heads/a bbbb222
update refs/heads/b cccc333
prepare
commit
EOF
```

`prepare` 后任何一条失败，`abort` 可整体回滚。这是 `git fetch` 自己更新几十个远端跟踪引用时用的同一套机制。

## 这条命令在流程里解决什么问题

`git update-ref` 解决的是"需要以底层方式直接更新引用（创建、修改或删除分支和标签）"的问题。它绕过高层命令（如 `git branch`、`git tag`），直接操作引用文件，支持原子性的旧值校验。

## 典型用例

- 在脚本中创建或移动分支，用 `git update-ref refs/heads/feature HEAD` 将 feature 分支指向当前提交。
- 原子性地更新引用并防止并发冲突，用 `git update-ref refs/heads/branch NEW_HASH OLD_HASH`，只有当旧值匹配时才更新。
- 删除一个引用，用 `git update-ref -d refs/heads/old-branch` 直接删除分支引用。

## 特殊情况与边界

- `git update-ref` 是写操作，直接修改引用指向。创建或移动分支、标签等引用都会改变仓库的状态。
- 使用旧值校验（第三个参数）可以实现原子性的条件更新：只有当引用的当前值与预期旧值一致时才更新，防止并发场景下静默覆盖别人的更新。
- 直接写引用时绕过了 `git branch`、`git tag` 等高层命令的验证和保护，拼错引用名可能意外创建不需要的分支。
- `update-ref` 不检查目标 hash 是否指向有效的提交对象——即使 hash 不存在，引用也会被创建。
- 使用 `-d` 删除引用时，如果引用不存在会报错；加 `-no-deref` 可以删除符号引用本身而不是它指向的目标。
