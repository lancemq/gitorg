# git-grep 教程

## 先想一个问题

`git grep` 搜的是某个版本里的已跟踪内容。这正是它比 `grep -r` 好用的原因：不碰被忽略的文件、不碰构建产物，而且 `git grep <pattern> <commit>` 直接搜历史而不是工作区。`-n`、`-w`、`-l`、`--and` 能覆盖大多数真实查询。

## 基本示例

```bash
git grep "TODO"
```

## 高频用法组合

```bash
# 只搜某个目录
git grep "TODO" -- src/

# 搜历史：v1.0 标签里有没有这个函数
git grep "parseConfig" v1.0

# 正则 + 行号 + 上下文（语义与 GNU grep 对齐）
git grep -nE "user_(id|name)" -- '*.ts'
git grep -B2 -A2 "deprecated"

# 布尔组合：同时含 A 和 B 的行
git grep -e "fetch" --and -e "timeout"

# 统计每个文件的命中数
git grep -c "useState"

# 搜暂存区（add 之后还没 commit 的内容）
git grep --cached "secret"
```

## 和 grep -r / ripgrep 怎么选

`git grep` 的优势在两点：**只搜已跟踪文件**（不会翻到 `node_modules` 和构建产物），以及**能直接搜任意提交**——`git grep "x" HEAD~30` 不需要 checkout。但它没有 ripgrep 的多线程和智能大小写，纯工作区搜索场景 ripgrep 通常更快。

经验法则：搜当前工作区用 ripgrep；搜「某个历史版本」用 `git grep <pattern> <commit>`，这一点 ripgrep 做不到。

## 特殊情况与边界

- `git grep` 默认只搜索已跟踪文件，.gitignore 中的文件不会被搜索到。
- 可以使用 `--and`、`--or`、`--not` 组合多个搜索模式，实现更精确的匹配。
- 搜索范围可以通过指定提交、树对象或路径来限制，比如 `git grep "TODO" v1.0 -- src/`。
- 在大型仓库中，git grep 通常比系统 grep 更快，因为 Git 只遍历索引中的文件而不是扫描整个文件系统。
