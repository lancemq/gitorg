# git rm 教程

```bash
git rm notes.txt              # 删文件 + 暂存删除
git rm -r legacy-folder/      # 删目录
git rm --cached .env.local    # 只停止跟踪，文件留在磁盘
```

`git rm` 做的事和 `rm` + `git add -u` 完全一样，区别只是「一步完成」和「意图明确」。所以它真正的价值不在命令本身，而在于它**会拒绝让你误删**。

## 与系统 rm 的关系

```bash
rm notes.txt && git add -u      # 等价
git rm notes.txt                # 一步完成，且会先检查
```

差别在检查：`git rm` 会拒绝删除有未暂存改动的文件，`rm` 不会。这个保护是它有价值的唯一理由。

```bash
echo "draft" >> notes.txt
git rm notes.txt
# error: the following file has local modifications:
#     notes.txt
# (use --cached to keep the file, or -f to force removal)
```

`-f` 强制删除，代价是**那部分未提交的改动永久消失**。如果那段改动还没进过任何提交，Git 帮不了你。

## --cached：停止跟踪，保留文件

最常见的用法是「文件已经被提交过，现在想让它回到被忽略的状态」：

```bash
git rm --cached .env.local
echo ".env.local" >> .gitignore
git commit -m "chore: stop tracking local env file"
```

顺序很重要：**先 `--cached` 再写 `.gitignore`**。反过来的话，文件已经在索引里，加进 `.gitignore` 不会自动生效——忽略规则只作用于未被跟踪的文件。

要一次清空整个索引重新开始（常见于 `.gitignore` 写太晚、误提交了 `node_modules`）：

```bash
git rm -r --cached .
git add .
git commit -m "chore: re-apply gitignore"
```

这会生成一个巨大的 diff（所有文件都变成删除 + 新增），但 `git diff --cached -M` 能看出大部分是重命名检测。谨慎使用——在已有历史的仓库上，它会把整个索引重写一遍。

### --cached 不会清除历史

这是最需要说清的一点。`git rm --cached` 只是让文件在**下一次提交**里消失，之前的历史仍然完整保留着那个文件：

```bash
git rm --cached secrets.env
git commit -m "remove secrets"
git log --all --oneline -- secrets.env
# 3f2a91c remove secrets
# 8b1d44e add secrets     ← 内容还在这里
```

任何人 clone 这个仓库，都能 `git show 8b1d44e:secrets.env` 拿到原文。

真正清除需要改写历史（`git filter-repo`），并且必须假设「已经泄露」——轮换密钥比清理历史更优先。

## 恢复误删

删除还没提交时：

```bash
git restore --staged notes.txt    # 先取消暂存的删除
git restore notes.txt             # 再从 HEAD 恢复到工作区
```

删除已经提交、还没推送：

```bash
git restore --source=HEAD~1 notes.txt
git commit -m "restore notes"
```

或者直接回退那个提交（如果它是最后一个）：

```bash
git reset --soft HEAD~1    # 撤销提交，保留索引
git restore --staged notes.txt
git restore notes.txt
```

已经推送的删除，用 `git revert` 生成反向提交，不要改写公共历史。

## -n 试跑

批量删除前先看会删什么：

```bash
git rm -r --dry-run legacy/
# rm 'legacy/a.ts'
# rm 'legacy/b.ts'
```

`--dry-run`（`-n`）只打印，不动文件。目录里有几十个文件时值得先跑一次。

## 常见错误

**对未跟踪文件用 git rm**：

```bash
git rm untracked.txt
# fatal: pathspec 'untracked.txt' did not match any files
```

未跟踪的文件不归 Git 管，直接用 `rm`。要清理一批未跟踪文件，用 `git clean -n` 先看，再 `git clean -fd`。

**以为 --cached 能清掉敏感信息**。见上文，它只影响下一次提交。

**在子目录里 `git rm -r .`**。`.` 指当前目录，只删这个目录下的文件。要清整个索引必须在仓库根目录执行。

**删除后忘了提交**。`git rm` 只是暂存删除，`git status` 会显示 `D`，但文件在磁盘上已经没了。此时 `git restore --staged` + `git restore` 可以救回来——前提是删除还没提交。

## 与 git mv 的对称性

`git mv` 在底层就是「`git rm` 旧路径 + `git add` 新路径」的组合。理解这一点之后，两个命令的行为都可预测：

```bash
git mv a.ts b.ts
# 等价于
git rm --cached a.ts && mv a.ts b.ts && git add b.ts
```
