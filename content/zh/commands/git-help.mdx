# git-help 教程

## 一句话理解

git-help 用于查阅命令帮助和手册页。

## 什么时候适合用

- 当你需要查阅命令帮助和手册页
- 当你想把这类操作做成稳定流程而不是手工重复
- 当你需要更准确地理解 Git 在这一步到底记录了什么

## 基本示例

```bash
git help rebase
```

## 读这条命令时最该注意什么

先把默认行为弄清楚，再去组合更多参数，通常能少踩很多隐藏规则。

## 一个更稳的实践建议

把它和 status、log、diff 一起看，更容易确认到底改了什么。

## 补充理解角度

- 理解这条命令的默认行为
- 把它放进日常提交或排查流程
- 在脚本或团队习惯里稳定复用


## 这条命令在流程里解决什么问题

`git help` 解决的是"需要了解某个 Git 命令的具体用法、参数和选项"的问题。它打开指定命令的手册页（man page）或在终端显示帮助信息，是学习和排查 Git 命令用法的首要入口。

## 典型用例

- 忘记某个命令的参数时，用 `git help rebase` 打开 rebase 的完整手册页，查看所有可用选项和示例。
- 在终端快速查阅命令概要，用 `git rebase --help` 在终端显示帮助文本而不打开 man 页面。
- 用 `git help --web <command>` 在浏览器中打开 HTML 格式的文档，适合不习惯 man 页面的用户。

## 特殊情况与边界

- `git help <command>` 和 `git <command> --help` 功能相同，前者调用 man 页面，后者在终端显示帮助文本（具体行为取决于配置）。
- `git help` 依赖系统的手册页系统，某些最小化安装的环境可能缺少 Git 文档包，需要额外安装。
- 用 `git help --guides` 可以查看 Git 的概念指南（如 gitworkflows、gitrevisions 等），不只是具体命令的帮助。
- `git help` 查阅的是本地文档，不需要联网，但文档版本与安装的 Git 版本一致，可能不是最新版本。
- 对于自定义别名，`git help <alias>` 会显示别名展开后的命令帮助，而不是别名本身的说明。


## 延伸阅读

继续搭配 git status、git log、git show 一起看，通常更容易判断这条命令对历史、索引和工作区分别造成了什么影响。
