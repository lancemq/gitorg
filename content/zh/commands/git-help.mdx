# git-help 教程

## 先想一个问题

`git help <cmd>` 和 `git <cmd> --help` 打开的是同一套文档，区别只在渲染方式：前者调 man 页，后者在终端里输出。真正会卡住人的是环境问题——最小化镜像里没装 `git-doc`、`man` 不可用、以及 `git help --web` 需要的浏览器。

## 基本示例

```bash
git help rebase          # man 页（最完整）
git rebase --help        # 等价
git help -g              # 列概念指南：gitworkflows、gitrevisions、gitsubmodules…
git help -a              # 列全部命令，含 plumbing
```

## 环境问题的解法

最小化 Docker 镜像里 man 页通常是缺的，报错形如 `No manual entry for rebase`。三条路：

```bash
# Debian/Ubuntu：装 git-doc（man 页）+ git 概念文档
apt-get install -y git-doc

# 不装文档，直接看网页版（读取 web.browser 或默认浏览器）
git help --web rebase

# 只想快速看参数，不想离开终端
git rebase -h        # 短帮助（注意是 -h，不是 --help）
```

`-h` 和 `--help` 的差别值得记：`-h` 由 git 本体输出、永远可用；`--help` 要起 man 或浏览器，依赖文档包。CI 脚本里查参数一律用 `-h`。

文档版本与本机 git 版本严格对应——`git help pull` 看到 `--rebase=interactive` 与否，先确认 `git --version`，再对照网页文档。


## 特殊情况与边界

- `git help <command>` 和 `git <command> --help` 功能相同，前者调用 man 页面，后者在终端显示帮助文本（具体行为取决于配置）。
- `git help` 依赖系统的手册页系统，某些最小化安装的环境可能缺少 Git 文档包，需要额外安装。
- 用 `git help --guides` 可以查看 Git 的概念指南（如 gitworkflows、gitrevisions 等），不只是具体命令的帮助。
- `git help` 查阅的是本地文档，不需要联网，但文档版本与安装的 Git 版本一致，可能不是最新版本。
- 对于自定义别名，`git help <alias>` 会显示别名展开后的命令帮助，而不是别名本身的说明。
