# Gitea 自建 Git 服务

## 学完这篇你会掌握什么

- 理解 Gitea 的定位：极轻量自托管 Git 服务，适合小团队 / 个人，资源占用远低于 GitLab CE
- 掌握两种安装方式（单二进制 / Docker）与首次安装页面的关键配置项
- 知道日常备份（`gitea dump`）与升级的基本流程，避免数据丢失
- 能根据团队规模在 Gitea、GitLab CE、GitHub 之间做出初步选型判断



## 先想一个问题

你想把代码托管在自己能完全掌控的机器上——可能是为了数据不出公司内网，也可能是嫌 GitHub 的私有仓库不够用、GitLab CE 又太重。Gitea 正好卡在中间：一个二进制文件就能跑起来，128MB 内存就够。但它真的能撑住你团队的日常协作吗？这篇带你把它装起来、配好、并知道什么时候该换更重的方案。

## 一句话理解

Gitea 是一个用 Go 写的轻量级自托管 Git 服务，用一个二进制文件即可运行，把"自己的代码仓库"的门槛降到最低。

## 概述

Gitea 是一个用 Go 编写的轻量级自托管 Git 服务。相比 GitLab CE，Gitea 资源占用极低（128MB 内存即可运行），适合小团队或个人使用。

## 安装

### 方式一：二进制安装（推荐）

```bash
# 下载最新二进制文件
wget -O gitea https://dl.gitea.com/gitea/1.22/gitea-1.22-linux-amd64
chmod +x gitea

# 创建运行用户
sudo adduser --system --group --disabled-password --shell /bin/bash --home /home/git git

# 创建必要目录
sudo mkdir -p /var/lib/gitea/{custom,data,log}
sudo chown -R git:git /var/lib/gitea
sudo chmod -R 750 /var/lib/gitea

# 启动
sudo -u git ./gitea web
```

### 方式二：Docker 部署

```yaml
# docker-compose.yml
version: "3"
services:
  gitea:
    image: gitea/gitea:1.22
    ports:
      - "3000:3000"
      - "222:22"
    volumes:
      - ./gitea-data:/data
    restart: always
```

```bash
docker compose up -d
```

## 初始配置

浏览器访问 `http://localhost:3000`，首次访问进入安装页面：

| 配置项 | 推荐值 |
|--------|--------|
| 数据库 | SQLite（小团队）或 PostgreSQL |
| 域名 | 自定义域名或 IP |
| SSH 端口 | 222（如果使用 Docker 端口映射） |
| HTTP 端口 | 3000 |
| 管理员账号 | 立即创建 |

## 日常管理

### 备份

```bash
# Gitea 内置备份命令
sudo -u git ./gitea dump -c /etc/gitea/app.ini

# 备份文件包含：数据库、仓库数据、配置、日志
# 输出在 /var/lib/gitea/data/
```

### 升级

```bash
# 1. 停止服务
sudo systemctl stop gitea

# 2. 备份
sudo -u git ./gitea dump

# 3. 替换二进制文件
cp gitea-old gitea-new

# 4. 重启
sudo systemctl start gitea
```

### 配置

```INI
# /etc/gitea/app.ini
[server]
DOMAIN = git.example.com
ROOT_URL = https://git.example.com/
HTTP_PORT = 3000
SSH_DOMAIN = git.example.com

[database]
DB_TYPE = sqlite3
PATH = /var/lib/gitea/data/gitea.db

[mailer]
ENABLED = true
SMTP_ADDR = smtp.example.com
```

<TipBox title="生产环境务必放在反向代理后面并强制 HTTPS">
  文中 `ROOT_URL` 直接用 `http://` 仅是演示。上线后应把 Gitea 放在 Nginx / Caddy 后，由反向代理终结 TLS，并把 `ROOT_URL` 改为 `https://`。SSH 端口若用 Docker 映射（`222:22`），记得在 `SSH_DOMAIN` 和 clone 地址里保持一致，否则别人 clone 会连错端口。
</TipBox>

## 与其他方案对比

| 特性 | Gitea | GitLab CE | GitHub |
|------|-------|-----------|--------|
| 内存要求 | ~128MB | ~4GB | SaaS |
| 安装复杂度 | 低 | 高 | 无需安装 |
| CI/CD | 内置 Actions | 内置 CI | Actions |
| 代码审查 | 支持 | 支持 | 支持 |
| 团队管理 | 基础 | 丰富 | 丰富 |
| 迁移工具 | 有 | 有 | 有 |

## 给你的练习

1. 用 Docker Compose 起一个 Gitea 实例（`3000` 映射 HTTP、`222` 映射 SSH），在浏览器完成首次安装，创建一个测试仓库并 clone 成功。
2. 执行一次 `gitea dump` 备份，确认产物里包含数据库与仓库数据；然后模拟一次升级（替换二进制 + 重启），验证数据还在。
3. 在 Gitea 里新建一个组织和一个成员账号，体验它与"纯个人仓库"在权限上的区别，对照文中对比表判断它是否适合你的团队规模。
