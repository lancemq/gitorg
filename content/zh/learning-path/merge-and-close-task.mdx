# 合并并关闭任务闭环

PR 被批准只是中间节点，真正结束是“主线已稳定 + 分支已清理 + 任务状态已更新”。

## 合并前检查

1. required checks 全绿
2. 审批状态满足规则
3. 目标分支仍是最新

## 合并后动作

```bash
git switch main
git pull --ff-only
git branch -d feature/first-pr
git push origin --delete feature/first-pr
```

## 为什么要清理分支

分支不清理会让后续协作噪声增加，也会掩盖真正活跃任务。

<WarningBox title="不要合并后就离开">
  若不更新任务状态与回归验证结果，团队会出现“代码合了但没人确认上线效果”的盲区。
</WarningBox>
