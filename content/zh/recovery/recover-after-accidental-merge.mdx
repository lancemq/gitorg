误 merge 最容易出问题的点是：不知道该用 `reset` 还是 `revert -m`。


## 先想一个问题

你刚刚在 Git 里做了一个操作，结果发现不是你想要的效果——甚至可能弄丢了提交。这种情况不是第一次了，你想建立一套可靠的方法来应对各种误操作场景。

## 关键判断

1. 这个 merge commit 是否已推送共享？
2. 是否有人基于它继续开发？

## merge 后第一轮检查

```bash
git log --oneline --graph --decorate -n 20
git branch -vv
git reflog
```

## 恢复方法

### merge 未共享

可以考虑回到 merge 前：

```bash
git reset --hard HEAD~1
```

### merge 已共享

应优先创建反向提交：

```bash
git revert -m 1 <merge-commit>
```

`-m 1` 表示保留第一父分支视角。

## 为什么不建议共享分支直接 reset

因为 reset 会重写公共历史，协作者会遇到分叉和同步冲突，后续治理成本更高。

<WarningBox title="先确认 parent，再执行 revert -m">
  对 merge commit 使用 `revert -m` 前，要明确主线是哪一侧父提交。父选择错误会把不该撤销的内容撤掉。
</WarningBox>
