# 发布清单纪律

## 学完这篇你会掌握什么

- 理解 发布清单纪律 的核心作用和适用场景
- 掌握 发布清单纪律 的基本用法和常用参数
- 通过固定发布清单把关键检查项前置并标准化，降低“靠经验记忆”导致的线上发布遗漏与事故。
- 理解 最小清单结构 相关的概念
- 掌握 执行原则 相关的操作
- 知道在什么场景下使用该命令，什么场景下避免使用


发布事故很多不是技术难题，而是基础步骤遗漏。清单的价值是把“应做但易忘”的动作固化。


## 先想一个问题

你的团队在 Git 使用上积累了一些习惯，但你不确定这些习惯是否最优——或者你刚经历过一次因为 Git 操作不当造成的事故，想知道怎么避免下次再犯。

## 最小清单结构

1. 版本与变更范围确认
2. 数据迁移与回退策略确认
3. 监控与告警阈值确认
4. 发布后验证与值班确认

## 执行原则

- 每项要有负责人
- 每项要可验证，不写空泛措辞
- 失败项不能“先发布后补”

## 示例检查项

- `git tag` 对应版本号与变更单一致
- 回滚命令在预发已演练
- 关键看板已设置发布窗口标记

<WarningBox title="清单不是形式化打勾">
  如果执行时不验证证据（日志、截图、命令结果），清单会退化为仪式，无法真正降低风险。
</WarningBox>

## 给你的练习

1. 在一个测试仓库中练习该命令的基本用法，观察执行前后的状态变化
2. 尝试该命令的不同参数选项，对比输出结果的差异
3. 模拟一个需要使用该命令的实际场景，完整走一遍操作流程
