# 代码评审交接质量

## 学完这篇你会掌握什么

- 通过高质量 review handoff（背景、范围、风险、验证）减少评审往返沟通成本并提升合并决策速度。
- 理解 高质量 handoff 的四要素 相关的概念
- 掌握 提交 PR 时建议附带 相关的操作

## 先想一个问题

你或者你的团队可能已经在用代码评审交接质量了——但用法对不对？有没有踩在边界上？这篇带你把代码评审交接质量的前提、边界和常见误用重新过一遍，很多隐患在变成事故之前就能排掉。

## 高质量 handoff 的四要素

1. 背景：为什么要改
2. 范围：改了哪些边界，不改哪些
3. 风险：潜在影响面
4. 验证：如何证明改动有效

## 提交 PR 时建议附带

- 关键变更点列表（3-7 条）
- 风险检查项
- 本地或预发验证结果
- 需要 reviewer 特别关注的文件

## 对 stacked PR 的补充

每层 PR 要说明依赖关系，并强调“本层新增差异”，避免 reviewer 重复阅读。

<WarningBox title="不要把 reviewer 当成需求背景探测器">
  如果上下文全靠 reviewer 自己补全，评审必然变慢且判断质量波动更大。
</WarningBox>
