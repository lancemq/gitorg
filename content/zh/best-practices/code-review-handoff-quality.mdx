# 代码评审交接质量

## 学完这篇你会掌握什么

- 理解 代码评审交接质量 的核心作用和适用场景
- 掌握 代码评审交接质量 的基本用法和常用参数
- 通过高质量 review handoff（背景、范围、风险、验证）减少评审往返沟通成本并提升合并决策速度。
- 理解 高质量 handoff 的四要素 相关的概念
- 掌握 提交 PR 时建议附带 相关的操作
- 知道在什么场景下使用该命令，什么场景下避免使用


评审效率低通常不是 reviewer 慢，而是交接信息不完整。


## 先想一个问题

你的团队在 Git 使用上积累了一些习惯，但你不确定这些习惯是否最优——或者你刚经历过一次因为 Git 操作不当造成的事故，想知道怎么避免下次再犯。

## 高质量 handoff 的四要素

1. 背景：为什么要改
2. 范围：改了哪些边界，不改哪些
3. 风险：潜在影响面
4. 验证：如何证明改动有效

## 提交 PR 时建议附带

- 关键变更点列表（3-7 条）
- 风险检查项
- 本地或预发验证结果
- 需要 reviewer 特别关注的文件

## 对 stacked PR 的补充

每层 PR 要说明依赖关系，并强调“本层新增差异”，避免 reviewer 重复阅读。

<WarningBox title="不要把 reviewer 当成需求背景探测器">
  如果上下文全靠 reviewer 自己补全，评审必然变慢且判断质量波动更大。
</WarningBox>
