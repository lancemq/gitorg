# GitHub CODEOWNERS 与评审归属

## 学完这篇你会掌握什么

- 通过 CODEOWNERS 建立文件级评审归属，减少关键模块无人负责或评审漂移的问题。
- 理解 设计原则 相关的概念
- 掌握 与分支保护联动 相关的操作

## 先想一个问题

关于 GitHub CODEOWNERS 与评审归属，你的理解可能停留在"知道怎么操作"，但说不清它为什么这样设计、边界在哪里。恰恰是这些说不清的地方，最容易在关键时刻出问题。这篇把 GitHub CODEOWNERS 与评审归属从"会用"推进到"理解"。

## 设计原则

1. 按模块边界定义 owner，不按个人临时分工
2. 避免单点 owner，关键模块至少双 owner
3. 定期同步组织结构变化

## 与分支保护联动

当开启 “require review from code owners”，关键文件变更会自动触发 owner 审批门禁。

<WarningBox title="CODEOWNERS 过细会导致评审拥堵">
  规则颗粒度过小会让 PR 频繁触发大量 owner，反而降低吞吐。
</WarningBox>
